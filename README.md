# 校园通知任务台

把班级群、课程群和邮件里的通知，整理成可核对、可提醒、可完成的待办。桌面端左侧是通知工作台，右侧默认是在线测试区「整理我的通知」；手机端改用「添加通知 / 待办 / 原文依据」三个单栏分区切换。模拟消息降级为「没有素材？体验一个案例」。

产品原则：

- **已读不等于已完成**。阅读状态与完成状态相互独立。
- **每条待办都能回到原文**。`sourceQuote` 必须是原文或对应截图转写中的连续片段；截断、拼接或伪造的摘录会被降级为待确认。
- **只对可核实的日期行动**。明确日期必须与原文时间表述一致；「这周五还是下周五」这类歧义返回空日期并标为待确认。
- **不冒充在线结果**。`cloud_agent`、`local_fixture`、`verified_offline` 三种来源分别标注，本地样例不会伪装成 Cloud Agent。
- **不监听聊天软件**。入口是用户主动粘贴文字或上传截图，不做微信、QQ、邮箱、企微、钉钉的消息接入。

## 在线整理：多段文字 + 多张截图，一次整理

右侧「整理我的通知」支持：

- 连续添加多段通知文字，最后一次性整理，不再每贴一条就拆一次。
- 添加最多 4 张 PNG / JPEG / WebP 截图，可点击选择文件，也可直接把图片拖到截图区；大图会在浏览器内压缩。
- 同一批文字与截图合并成一个通知；截图和文字会一起送给 Qoder Cloud Agent 拆解。
- 截图转写只写图中确实可见的内容；模糊、裁切、遮挡或无法确认时如实标不确定，相关候选强制进入待确认，不会假装读全。
- 通知提到群文件或附件、但截图里没有附件内容时，界面会提示回原聊天软件自行下载，不会假装已经拿到文件。
- 视觉能力不可用或请求失败时明确报错，保留草稿，不自动改用离线样例，也不写入编造结果。

模拟消息仍在右侧「模拟消息」标签内，只用于没有素材时体验；它不是主入口。

## 核对、修改与去重

拆解完成后先打开核对窗口，而不是直接写待办。核对改为「先决定、再按需编辑」：

- 一次只展示一条候选；多条时用「第 1 / 2 条」和上/下一条切换，不再把多张完整表单叠在一屏。
- 卡片顶部是标题和一句要做什么的摘要；「要办 / 稍后 / 与我无关」放在最显眼的位置，先决定是否加入。
- 时间、地点、材料、补充要求和提醒收成小信息条，点一下才展开编辑。没有识别到日期时显示「未识别到日期，可手动补上」，不会出现 yyyy/mm/日 这类空日期占位。
- 日期按文本输入，接受 `2026-11-26`、`2026/11/26`、`2026年11月26日` 等写法；原文有具体时刻或用户手动补时刻时，同时显示和编辑 24 小时制时刻。活动、会议、答辩等事项显示「开始」，提交类事项显示「截止」。
- 确认卡片固定展示相对原文时间，例如「原文：今天下午；具体日期待确认」，不会把相对时间猜成绝对日期。
- 原文里的办理网址、报名或评价链接会在摘要和任务卡片中直接显示，可点击打开；默认摘录会覆盖关键要求。
- 学号、身份证后六位、初始密码、验证码、VPN/登录说明不会进入「材料」；材料只保留需要携带或提交的实物、表格和证件。
- 仅阅知候选默认选「与我无关」、不加入待办；只有用户明确点「要办」才会生成待办。
- 标题和动作默认只读摘要，需要时点「改标题或说明」展开。
- 待确认候选仍需一行「我已核对原文」确认，并补上明确截止日期，才可转为「需办理」；截图仍有不确定内容时不能直接转。
- 只有系统判断可能与已有任务重复或变更时，才出现关系提示，并用「仍新建 / 合并 / 更新 / 跳过」按钮选择；没有用户选择不会改动已有任务。
- 「未生成待办的片段与原因」默认收起成一句，点开才看列表。
- 原文摘录、对应截图和模型转写默认收起，按需展开；保存后的任务卡片同样可以回看依据。
- 标记「与我无关」的候选不会加入待办，但原通知仍会保存，方便回看。
- 保存成功后清空当前批次草稿（文字与截图），右侧保留「继续添加通知」入口，避免重复整理；已保存的通知留在通知列表和看板里。

## 手机使用与限制

- 手机顶部固定三个分区：「添加通知」添加文字/截图并整理；「待办」查看优先处理、提醒与逐条待办；「原文依据」查看当前通知原文、截图与高亮原句。看板仍可从「待办」里的「查看全部未完成」进入，不额外占用一个手机分区。
- 「整理这批通知」吸底显示，已为 Home Indicator 和右下角 Qoder 标识留出空间；核对窗口使用 `100dvh` 上限并在内部滚动，保存栏不会被标识挡住。
- 截图区在每个宽度下都能连续添加、逐张预览和删除；主要按钮和勾选框按约 44px 触控目标处理。
- 长链接、长原文和较多标签会自动换行，页面不允许横向滚动。
- 提醒条与「现在处理 / 推迟」选项在「待办」、看板，以及「添加通知」「原文依据」顶部都能看到；关闭网页后仍无法继续提醒，这一点没有改变。

## 首页优先区与提醒

左侧顶部优先显示：

- 已提醒但未处理的任务；
- 已过期任务；
- 3 天内截止的任务；
- 其他未完成事项（包括没有日期、需要确认和 3 天以后到期的任务），并提供「查看全部未完成」进入看板。

页头、优先区、看板统计都只统计当前可见且可打开的任务，不把隐藏通知里的旧引用或已清理的本地引用算进去。看板页也保留提醒收件箱。

提醒可在核对候选或任务详情里设置：提前一天、提前两小时、自定义时间；在提醒编辑里提供「设为 1 分钟后（测试系统通知）」。自定义提醒使用中文日期加 24 小时「时 / 分」选择，不出现 `11/22/2026, 10:57 AM` 这类英文 12 小时格式。到点后：

- 页面内收件箱出现「现在处理」和「15 分钟后 / 1 小时 / 今晚 20:00」推迟选项；
- 用户授权系统通知后，通过 Service Worker（`public/notify-sw.js`）发出 Windows 通知中心或 macOS 通知，使用系统默认提示音，带「现在处理」「稍后再叫我」操作，并设置 `requireInteraction` 避免一闪而过；
- 只要站点标签页仍开着（即使切到其他软件或后台标签），到点都会检查并发出系统通知；
- 桌面系统或浏览器可能不渲染通知上的操作按钮；此时点击通知会回到任务台，页内收件箱仍提供完整操作；
- 未完成且未推迟的任务会再次提醒，但同一提醒 60 分钟内不重复，用户点过「现在处理」后 2 小时内不再打扰；
- 通知区域始终显示「未授权 / 已允许 / 已拒绝 / 当前浏览器不支持」及原因，并提供「发送测试通知」；未授权或已拒绝时按钮会说明不能发送的真实原因，不会伪装成功；
- 重开应用时，到点未确认的提醒会重新出现在优先处理区。
- 已在本机验证到点后确实发起带「现在处理 / 稍后再叫我」、`requireInteraction` 和 `renotify` 的系统通知调用，并验证推迟与「现在处理」回写；Windows/macOS 系统通知的真实弹窗需要浏览器授权，未授权的环境不会伪造送达。

如实说明边界：关闭网页后，仅靠前端定时器无法在约定时间继续提醒。服务器定时推送或邮件提醒属于后续能力，本版本没有假装具备「关掉网页也能提醒」。

## 评委三分钟了解与跟随引导

页头「评委用户快速了解请点我」只有一屏产品说明：

- 标题「通知不再被淹没，待办会主动找人」；正文先讲学生和班级群、邮件里的真实问题，再说把文字或截图放进来后会发生什么，并明确不监听微信、QQ 或邮箱。
- 三张说明卡片只讲人话：只提取要办的事；每条都能对回原话或截图，重复通知会先问你是不是同一件；到点用电脑或手机的系统通知提醒，忙时可以稍后。
- 不再放 1–1.5 分钟分镜时间轴；故事交给「跟着走一遍」在真实界面演示。
- 页脚只保留这一句限制：「演示素材是虚构的校园通知；你的待办只保存在当前浏览器；关闭这个网页后，网页端无法继续提醒。」
- 两个主按钮：「跟着走一遍」载入演示截图并从第 1 步启动引导；「用我自己的通知试试」关闭说明并把焦点放到右侧「整理我的通知」输入框。
- 跟随引导的气泡贴在高亮目标旁边，并随真实操作自动推进：草稿就绪、打开核对、做出决定、选择合并/更新、保存。若当前候选没有相似任务，合并/更新这一步会明确提示「这次没有相似任务，已跳过」，不会伪造关系；有相似任务时必须使用真实核对界面选择。
- 结束页会说明保存后的通知留在通知列表和看板、草稿已清空，并可继续添加下一批。
- 演示截图 `public/demo/lab-safety-notice.png` 是虚构的「软件工程 2301 班」群通知，包含待办、闲聊、模糊时间、群文件附件和消防演练等场景。

## 图片识别路径与验证

复用内置 Qoder Cloud Agent 收图，不接阿里云，不做本地 OCR：

- 浏览器只请求同源 `/functions/v1/app?action=extract`；平台在服务端注入 `QODER_PAT`，前端和仓库没有模型密钥，评委和普通用户不需要提供任何 Key。
- 图片以纯 Base64 输入，最多 4 张，单张 ≤3.5M Base64 字符，总计 ≤8M 字符，服务端会校验图片魔数。
- 已完成最小收图验证：真实 Cloud Agent 请求返回 HTTP 200、约 23.3 秒、`mode: "cloud_agent"`、`imageReads` 覆盖输入图片，闲聊进入 `ignored`。
- 已在发布站点完成“浏览器 → 同源 Function → QCA”的完整截图路径验收：载入虚构群聊截图后得到 2 条候选、6 条未生成说明，核对弹窗和保存后的任务卡片都能展开原图与模型转写。
- 内置 Agent 支持图片输入，因此不采用阿里云后备。
- 没有配置视觉能力时，文字整理仍可用；截图会明确提示暂不可用，不会显示为成功。

## 本地开发

需要 Node `^22.13.0 || >=24.0.0`。

```sh
npm ci
npm run dev   # 5174，监听 0.0.0.0；不要占用其他项目的 5173
```

Vite 把 `/functions/v1/app` 代理到本仓库自己的本地函数 `127.0.0.1:8001`。另开一个终端启动它：

```sh
npm run dev:function:node   # Node 适配器，无需 Deno，也不需要 .env
# 或已安装 Deno 时：npm run dev:function
```

本地函数监听 `0.0.0.0:8001`，与 `8000` 上其他项目的函数互不影响；不要为了本地预览去改、停止或占用 `8000`。本地预览只对已核对样例返回 `local_fixture`：

- 内置演示截图 `public/demo/lab-safety-notice.png`（按文件字节 SHA-256 稳定识别）；
- `data/sample-notices.json` 里三段已核对文字（学生、辅导员、班级群）。

其它文字或截图会得到中文 503，明确说明“本地预览只对已核对样例走 local_fixture……公开站点才走 Cloud Agent”，不会伪造在线拆解成功。请求仍遵守本仓库 handler 的原限额：9 MB 请求体、12000 字、最多 4 张截图、单张 3.5M / 总计 8M Base64 字符；前端会在发送前按同一限额提示删图、压缩或改用文字，不会为了演示图放宽限额。

本地预览（`127.0.0.1` / `localhost`）不执行 Sites Function：未启动本地函数时请求会得到 HTTP 502，界面会明确提示先运行 `npm run dev:function:node`，不会写入任何结果。工作台的源码预览同理，在线文字与截图验收请使用公开站点地址。

```sh
npm test        # handler、任务状态、QCA、流水线、核对/去重/提醒/图片契约、主流程、界面一致性、请求预算、数据校验
npm run build   # 类型检查并输出 dist/
```

手动验证建议：

1. 点击「评委用户快速了解请点我」：应在第一屏内读完产品说明，没有分镜时间轴，页脚只有一句限制，两个按钮为「跟着走一遍」「用我自己的通知试试」。
2. 允许系统通知后整理一条通知并设置「1 分钟后」提醒，保存后切到其他窗口；到点应弹出 Windows/macOS 系统通知。点击「现在处理」回到任务台，或点击「稍后再叫我」把提醒推迟 15 分钟。再关闭整个网页，确认不会在约定时间继续提醒。
3. 整理一条包含多条候选的通知：核对窗口一次只显示一条，用「第 1 / 2 条」切换；先选「要办 / 稍后 / 与我无关」，再点日期信息条，未识别时看到「未识别到日期，可手动补上」；输入 `2026/11/26` 应规范为 `2026-11-26`。
4. 用一条与已有任务相似的新通知，确认关系提示只在真的可能重复时出现；选择合并、更新或仍新建，未选择时已有任务不变。
5. 点「添加截图」选择图片，或把图片直接拖进截图区；打开有截图来源的候选，确认可展开原图和转写，模糊截图的候选应保持待确认。
6. 刷新后检查通知、待办和修改后的截止日期仍在，且不会因原文含模糊时间被打回；页内收件箱中的已提醒未完成任务应重新出现。
7. 在 1280×800 窗口下确认右侧「整理这批通知」按钮不被右下角平台标识遮挡；点击「评委用户快速了解请点我」→「跟着走一遍」，引导应从第 1 步开始，引导气泡贴近当前目标且避开保存按钮和平台标识。
8. 先运行 `npm run dev:function:node`，在 5174 点「载入一张虚构的演示截图」→「整理这批通知」：确认页应标注 `local_fixture`，返回 2 条候选、1 张截图转写和 5 条未生成说明，不出现 413 或 Cloud Agent 标记。
9. 在 5174 粘贴三段已核对文字之一，同样应进入 `local_fixture` 确认页；粘贴任意未知文字或添加非演示截图，应看到中文 503 说明，而不是伪造成功。
10. 手机 360 / 390 宽：滚动「添加通知」时顶部分区导航保持可见；「原文依据」在没有已保存通知时显示空状态和「去添加通知」按钮；评委介绍弹窗可内部滚动，底部按钮不被裁切，并为平台标识预留空隙（本地没有真标识，不宣称已实测重叠）。
8. 对比优先处理区「N 件未完成」、通知列表待办数和看板统计，三者应一致；隐藏通知里的旧引用（例如「如需请假请私聊老师」）不应出现在任何计数或列表中，也无法从计数点开。
9. 整理包含「仅阅知」候选的通知：默认应为「与我无关」且不生成待办；只有点「要办」才会写入。保存后 Toast 与「查看处理过程」里的装配结果应使用同一句统计（例如「新增 3 条，跳过 1 条」），并清空本批文字与截图草稿。

- `src/components/JudgeDialog.tsx`、`src/lib/judge.ts`：评委产品说明与六步跟随引导。
- `public/notify-sw.js`：Service Worker 系统通知与「现在处理 / 稍后再叫我」点击回传。
- `src/lib/images.ts`：截图格式/大小/预算校验与浏览器压缩。
- `src/lib/review.ts`：审核决策、候选生成、合并/更新写入与通知装配。
- `src/lib/dedupe.ts`：相似度、材料重叠、变化项与合并/更新 patch。
- `src/lib/reminders.ts`：截止时刻解析、提醒计算、提醒抑制与优先排序。
- `src/lib/gates.ts`：连续摘录定位、日期门闸、闲聊过滤、图片证据与待确认规则。
- `src/lib/extraction.ts`：同源请求拆解函数，校验 `imageReads/ignored` 并做二次门闸。
- `src/lib/pipeline.ts`：六工位运行状态，通知内嵌展示。
- `functions/`：Sites Function 入口、请求边界、Cloud Agent 调用与结果规范化。
- `dev/test-review.mjs`：核对、去重、提醒、图片契约和评委引导测试。
- `dev/test-ux.mjs`：计数一致性、隐藏任务排除、旧引用清理、仅阅知默认、引导推进、草稿清理、中文时间、凭证过滤与通知状态测试。

## 部署与运行状态

前端构建到 `dist/`，同源函数位于 `functions/`，通过 Qoder Sites 的 `prepare_site` / `publish_site` 交付。浏览器只请求同源 `/functions/v1/app?action=extract`；模型凭证只由平台注入的 `QODER_PAT` 在 Function 内读取。

当前版本已发布，站点地址为 https://campus-notice-desk-3afax5pd62e.qoder.zone/ ；Function `app` 为 active / published。站点访问策略当前为邀请制（selected），未登录请求返回 HTTP 401；如果评委需要直接匿名打开，需要在站点设置里切换为 public（公开分享需单独确认）。线上版本包含逐条核对、评委单屏说明、系统通知与页内收件箱。

Function 只在服务端日志记录 `extraction_result` 的结果、任务数、图片数、错误码和耗时，不记录原文、截图内容、凭证或上游原始报错。

## 明确不做

不监听微信/QQ/邮箱/企微/钉钉，不做账号体系、多设备同步、自动回复、群发后台，不宣传“已接通所有聊天软件”。待办、提醒和已保存的通知只写入当前浏览器；整理时截图会随请求发送给 Cloud Agent 读取，不在任务台服务端另存。标签页保持打开时可以用系统通知提醒，关闭网页后无法继续提醒；服务器定时推送和邮件提醒不在本期范围内。
